# report

AI 면접 리포트 Feature(`FeatureReport`)의 도메인 노드. 화면 3개 + 메인 위 바텀시트 1개로 구성한다. 면접 종료 후 채점 결과를 사용자용 리포트로 보여주고, 영상 복기·지인 피드백 요청으로 잇는다. 기획→코드 매핑은 [ai-interview-report](../docs/work/ai-interview-report.md), 서버 계약은 [[api#Interview Report]].

## 코디네이터

`ReportFeature` — 1차 리포트를 루트로 두고 나머지 화면을 `path`(StackState)로 push 한다. 각 화면의 delegate 만 매칭한다(D5). 부모(AppFeature)로 올리는 것은 `closeRequested` 뿐 — 나머지 전환은 모듈 안에서 끝난다(분석 부족의 «다시 연습하기» 는 2026-08-06 제거).

**진입은 둘, 시작 화면도 둘이다.** 홈 위젯②의 [레포트 보기](2026-08-05 배선)와 마이페이지 리포트 줄의 두 버튼(2026-08-10)이고, 어느 쪽이든 AppFeature 가 세션 id 로 fullScreenCover 를 세우고 이탈 신호를 받는다 → [[app#Cross-feature Routing]]. 시작 화면은 `Entry` 가 가른다 — 기본은 메인(1차 리포트)이고, 마이페이지 [지인 피드백 받기] 만 `.peerFeedback` 으로 링크 생성 화면 위에서 시작한다(메인은 그래도 루트로 남는다 — 허브라 되돌아올 자리가 있어야 한다). **면접 정상 종료 → 리포트 직행은 하지 않기로 확정됐다**(2026-08-06) — 면접은 리포트 대기 화면에서 홈으로 돌아간다([[interview#코디네이터]]).

**메인이 허브다.** 화면들은 한 줄로 이어지지 않는다: 영상 플레이어는 리포트의 종속 화면이지 지인 피드백의 앞 단계가 아니고, 영상을 보지 않고 바로 지인에게 보낼 수 있어야 한다. 그래서 각 화면 진입은 메인의 개별 delegate(`videoRequested`·`peerFeedbackRequested`)가 트리거한다.

## 1차 리포트

`ReportMainFeature` — 루트이자 상세 화면. 요약 화면을 따로 두지 않는다(이탈 이력). `InterviewReportClient.report` 한 번으로 전 화면 데이터를 받고, `.generating` 이거나 `reportNotFound` 면 폴링한다 — **`reportNotFound`(404)는 에러가 아니라 미생성 상태라서 폴링을 계속한다**.

폴링 상한 초과(`pollTimedOut`)와 재시도 가능 에러는 화면의 «다시 시도하기» 버튼(`userTappedReload`)으로 되살린다 — 카운터를 리셋하고 재조회. 세션 없음·로그인 만료는 다시 눌러도 같은 답이라 버튼을 주지 않는다(정의서 §4-4).

**도메인이 케이스로 승격하지 않은 에러코드는 화면 문구로 번역할 수 없다** — 그 자리엔 클라가 지어낼 말이 없으므로 서버 원문을 공통 Alert(`serverAlertState()` — [[api#공통 규약]] 임시 노출 규칙)로 그대로 띄운다. 화면 자체는 평소의 실패 안내와 재시도 버튼을 그대로 쓴다(Alert 는 위에 얹힐 뿐). 당겨서 새로고침 실패도 같다 — 받아 둔 보고서는 지우지 않고(`reportRefreshFailed`) 미승격 에러만 Alert 로 알린다. 조용히 삼키면 원인이 사라진다.

**채점 실패(FAILED)는 정상 카드 경로에서 떼어낸 상태다**(`generationFailed` — ⚠️ prd-외 재량: PRD 는 이 UX 미확정, 오표기만 막은 임시 구현) — READY·INSUFFICIENT_ANALYSIS 와 한데 묶으면 headline 이 없어 «분석 부족» 폴백 문구가 떠 오표기된다. 문구는 홈 위젯 실패 행과 같은 계열(«레포트 생성에 실패했어요» + «이용권 횟수는 차감되지 않아요»)이고, 재조회해도 같은 답이라 재시도 버튼이 없다. 폴링도 여기서 멈춘다(UX 는 PM 확정 대기).

**늦게 도착한 지인 피드백은 당겨서 새로고침으로 받는다** (⚠️ prd-외 재량 — 갱신 흐름 스펙 대기 자리를 관례로 메웠다, 확정 시 재검토) — `onAppear` 는 이미 받아 둔 보고서를 다시 묻지 않아(재진입 재조회 없음) 화면에 반영될 길이 이것뿐이다. 폴링 재개가 아닌 **단발** 재조회고, 카드 선택·시트·접어 둔 툴팁을 건드리지 않는다. GENERATING 응답은 버린다 — 받아 둔 보고서를 그것으로 덮으면 화면이 빈다.

노출 금지: 종합점수·채용 판정·천장·항목 점수·레드플래그 원문. 사용자 문구는 대부분 서버 소유(`headline`·`card.questionIntentTitle`·`card.questionIntent`·`card.cardRedFlagNotices.message`·`card.resolutionNotice`)라 클라가 만들지 않는다 — 클라 하드코딩은 영상 카드 문구·안내 줄·nil 폴백·시트 마무리 문구뿐. 질문 의도 카드는 볼드 제목까지 서버 값이다(`questionIntentTitle` — 비면 그 줄만 뺀다).

**메인 카드에 서는 분석 카드는 «Hilit의 질문 분석» 하나뿐이다**(시안 443:7204 · `QuestionAnalysisCard`) — «Hilit의 답변 분석» 은 하이라이트 상세 시트 전용이라 메인에서 그리지 않는다. 해상도 안내·카드 레드플래그는 카드 본문에 서지 않는다 — 제목 옆 느낌표 툴팁으로 옮겼다(`MessageCard(.mini)` 한 줄 판은 상세 시트 전용).

**카드는 세로로 늘어놓지 않고 질문 탭으로 한 장씩 본다**(`selectedCardIndex`). 대본이 길어 전부 펼치면 스크롤이 무너진다. 폴링 중 카드 수가 줄면(분석 부족 확정) 선택 위치를 처음으로 되돌린다.

레드플래그 유무는 «상세 리포트» 제목 옆 느낌표로 알리고, 시안(443:7204·443:7264)대로 문구 툴팁을 **함께** 띄운다. **접힘은 State 수명 내내 유효하다** — 툴팁이나 느낌표를 눌러 접으면 `isRedFlagTooltipVisible` 은 그대로 false 로 남고 `onAppear` 도 되돌리지 않는다(재진입 복귀에도 다시 안 뜬다). 다시 뜨는 건 State 가 새로 만들어질 때, 즉 화면을 닫고 새로 진입할 때뿐이다 — 초기값 true 가 «한 번만 보여준다» 를 표현한다. 안내가 없으면 느낌표·툴팁 둘 다 그리지 않는다. 안내는 보고서 단위 필드가 아니라 **카드 소유**라, 툴팁은 지금 보고 있는 질문 카드(`selectedCardIndex`) 것만 세운다 — 탭을 옮기면 툴팁 내용이 그 카드 것으로 바뀌고, 안내 없는 카드에서는 느낌표까지 사라진다. 한 카드 안에서는 `resolutionNotice`(최대 1건) → `cardRedFlagNotices`(배열 전부) 를 줄바꿈으로 잇고, 건수 상한은 두지 않는다(빈 문자열만 버린다). 툴팁은 오버레이라 열고 닫아도 아래가 밀리지 않고, 제목 «위»에 뜬다(아래로 두면 질문 탭을 덮는다). 가로 위치는 좌표가 아니라 «꼬리 끝 = 느낌표 오른쪽 끝» 정렬로 잡는다(`DetailReportHeader`).

영상 카드의 남은 시청 시간은 State 가 아니라 View 의 `TimelineView` 가 `video.expiresAt` 에서 파생해 1초마다 그린다 — 리듀서에 1초 틱을 넣으면 폴링과 무관한 액션이 매초 흘러 테스트만 시끄러워진다.

**지인 피드백 섹션은 쌓인다, 바뀌지 않는다.** «지인에게 보내기» 요청 카드는 항상 남고(분모는 서버에 없어 `maxGuestCount` 상수 — «0/4» → «1/4»), 한 명이라도 남기면 그 **위에** 지인 이름 탭 + 고른 지인의 태도 평가 목록이 얹힌다. 카드를 목록으로 교체하면 정원이 차기 전에 다음 지인에게 보낼 길이 사라진다.

태도 평가는 **서버 배열 순서를 쓰지 않고** 정해진 축 순서(시선·표정·자세·손동작·목소리)로 다시 세운다(`GuestReview.orderedRatings`) — 지인을 바꿔가며 비교할 때 순서가 흔들리면 눈이 못 따라간다. 모르는 축 코드는 버린다(`AttitudeAxisKind`).

보고서 응답은 축 **코드와 1~4 단계만** 주고 표시 문구를 안 준다(게스트 제출측 `AttitudeAxis` 와 달리). 그래서 판정 문구·항목 이름·아이콘은 `GuestAttitudeCopy` 가 갖는다 — 시선·목소리는 제출 화면 확정 문구를 서술형으로 옮겼고, 표정 1단계(«밝아요.»)만 리포트 시안(443:7102)에 있어 그 칸을 따랐다. 나머지(표정 2~4단계·자세·손동작)는 그쪽도 확정 대기라 잠정이다.

## 하이라이트 상세 시트

`ReportHighlightDetailFeature` — 화면이 아니라 대본 하이라이트를 탭하면 올라오는 바텀시트. 리포트 카드와 영상 플레이어 STT 오버레이 **양쪽이 같은 리듀서를 재사용**한다.

차이는 `[영상 보러가기]` 노출 여부 하나(`showsVideoJump`) — **플레이어에서 올라온 시트는 늘 숨기고**(이미 영상 안이라 갈 곳이 없다, 2026-08-07), 메인에서는 재생할 영상이 없을 때 숨긴다. 그래서 그 delegate(`videoJumpRequested`)를 받는 쪽은 메인뿐이다.

시트는 `HighlightContext` 로 **문장이 아니라 대본 전체**를 받는다. 강조 구간 앞뒤를 흐린 색으로 함께 보여줘야 문맥이 남는다 — 문장만 넘기면 그게 사라진다.

톤(잘함/개선)은 강조 색·진단 카드 아이콘에 더해 «다음 대비» 판과 마무리 코칭 문구를 가른다 — 실제 분기 재료는 구간의 `reason` 이다: 파고들 여지(PROBE_WORTHY)면 꼬리질문, 딴 답(OFF_INTENT)이면 «질문 의도 ↔ 내 답변» 대조(`HighlightContext.IntentReview`), 그 외에는 블록 자체가 없다. 화면은 한 벌이고 판만 갈린다.

진단 카드 라벨은 톤과 무관하게 **언제나 «Hilit의 답변 분석»** 이고, 그 라벨이 서는 자리는 시트뿐이다 — 시트가 평하는 대상이 대본 구간(= 답변)이라서다. 메인은 «질문 분석» 만 그린다. 톤은 아이콘·다음 대비 판·코칭 문구만 가른다.

레포 최초의 `.sheet` 도입 지점이다(기존 사용처 0). 진단 카드 볼드 줄은 서버 `span.title`, 다음 대비 재료는 `reason` 이 채운다 — **재료가 비면 그 줄·블록을 렌더하지 않는다**(행동형 키워드 태그만 서버 확장 대기).

## 영상 플레이어

`ReportVideoPlayerFeature` — 리포트의 종속 화면. AVPlayer 는 State 에 두지 않고 View-local `@State` 로 소유한다(선례 `GuestVideoPlayerView`). 만료 판정은 플레이어 책임이 아니다 — 리포트가 `playableVideoURL` 에서 걸러 만료 시 진입 자체를 막는다.

**AVPlayer 는 뷰가, 재생 상태는 리듀서가** 갖는다. 컨트롤 자동 숨김·진행바 칸 채움·대본의 «현재 문장» 이 모두 재생 시각에 딸린 화면 상태라서다. 뷰로 내리는 이동 명령은 `seekToken`(단조 증가) + `seekTarget` 쌍 — 뷰가 토큰 변화만 보고 seek 해서, 같은 시각으로 두 번 이동해도 놓치지 않는다.

재생 실패(전송·디코딩)는 이 화면 몫이라 안내에 «다시 시도» 를 붙인다(⚠️ prd-외 재량 — 실패 UX 시안 없음, 관례 보강) — 문구만 두면 X 로 나가는 것 말고 할 게 없다. 실패한 AVPlayer 는 `play()` 로 살아나지 않으니 `reloadToken`(같은 명령 전달 방식)으로 뷰에 **재생성**을 시키고 보던 시각부터 다시 건다.

**자동 숨김은 딤과 재생 버튼만 걷는다** — 무입력 3초 뒤 그 둘이 사라져 영상만 남는다. 단, 일시정지 중에는 숨기지 않는다(다시 재생할 버튼이 사라진다). **하단 바(진행바·대본 버튼)는 붙박이라 숨김을 타지 않고**, 밝은 영상 위에서도 읽히도록 DS `VideoOverlay(.darkClose)` 스크림을 늘 깐다(대본을 켜면 오버레이가 제 `.darkOpen` 을 갖고 있어 겹쳐 깔지 않는다). **스크림은 둘 다 하단 세이프에어리어까지 내려간다** — 램프가 세이프에어리어 안에서 끝나면 홈 인디케이터 자리에 영상이 도로 드러난다. `.darkClose` 는 `ignoresSafeArea` 로, 대본 오버레이는 대본 위치를 흔들지 않으려 램프 «끝 색»(b900) 한 판을 아래로 이어 붙여 메운다.

**딤은 영상만 덮는다** — 재생 컨트롤·하단 바는 딤 위에 쌓아 색이 변하지 않는다(딤을 켜도 진행바 초록·대본 버튼 판이 그대로다). z 순서가 이 규칙의 유일한 구현이라 요소를 딤 아래로 옮기면 조용히 깨진다. 재생 컨트롤은 화면 가운데가 아니라 «네비 바 아래 ~ 진행바 위» 사이 가운데에 선다(Figma 443:7852 위아래 대칭).

**상세 시트가 올라오면 컨트롤을 전부 비운다**(상단 X 까지 — 사용자 결정 2026-08-06). 시트가 화면을 다 덮지 않아 위쪽 띠에 X 가 남고, 그 X 는 시트 밖이라 눌린다 — 눌리면 보던 하이라이트째로 플레이어를 떠난다. 시트를 내리는 게 먼저다. X 는 값(`leading` 슬롯)으로 비운다 — 모디파이어를 분기하면 뷰 identity 가 갈려 AVPlayer 를 쥔 `@State` 가 날아간다.

시간축은 서버 대본 발화에서 온다([[api#Interview Report]]): **진행바 칸 = 덩어리 = 카드(질문 턴)** 다(2026-08-07 확정 — 발화 하나당 칸 하나는 너무 잘게 쪼개져 폐기, 옛 `script` 기반 칸도 함께 폐기라 최상위 `script` 는 화면 사용처가 없다). 칸의 시간 범위와 오버레이 문장은 그 턴 발화 전체(`timelineSegments` — 면접관 질문 포함, 탭하면 질문부터 듣는다), 하이라이트 시각 폴백만 문자 오프셋을 가진 면접자 발화(`orderedSegments`)다. `VideoTranscript` 가 카드를 칸(`chunks`)·대본 줄(`lines`, 문장 단위)로 펼친다 — 발화가 아예 없으면 영상 전체 한 칸으로 물러난다.

**좌우 화살표도 초가 아니라 칸 단위**로 움직인다(`userTappedPreviousChunk`/`userTappedNextChunk`, 2026-08-05 — 옛 ±10초 폐기). «턴 = 이동 단위» 를 컨트롤까지 밀어붙인 것 — 화살표가 초를 세면 이동 결과가 진행바 칸과 어긋나 어디로 갈지 미리 보이지 않는다. 마지막 칸에서 오른쪽은 무반응이다(영상 끝으로 튀면 재생이 끝나 버린다).

**그릴 문장이 없으면 오버레이를 아예 얹지 않는다**(`isTranscriptOverlayVisible` = 켠 상태 + 현재 턴 있음, 2026-08-07). 서버 발화가 없는 보고서는 대본 토글 자체를 감추고, 첫 발화 앞에서는 켜도 뜨지 않는다 — 글자 없는 스크림이 화면을 덮으면 그 램프가 하단 스크림을 대신하면서 하단 바 그라데이션이 어긋난다. 하단 바 버튼 줄은 **높이 44 고정**이라 토글이 없어도 진행바가 내려앉지 않는다(오버레이 `bottomInset` 이 이 높이를 센다).

**대본 오버레이는 현재 턴 하나만, 문장을 재생 시각까지 쌓아** 보여준다(2026-08-07 확정 — 옛 전체 카드 나열 폐기). 규칙 하나가 진입 경로 둘을 다 덮는다: «시작 시각이 지난 문장만 그리고, 현재 문장은 항상 맨 아래». 처음부터 재생하면 문장이 밑에서 차곡차곡 올라오고, 하이라이트 점프로 중간부터 들으면 그 시점까지 쌓인 채 목표 문장이 바닥에 선다 — 별도 분기가 없다. 대본 최고점은 네비 바 아래 182 — 위로 밀려난 문장은 상단 페이드로 사라지고, 넘치면 스크롤로 되짚는다. **새 문장이 오면 바닥으로 스냅**한다(위로 읽던 중이어도 — 현재 문장 = 바닥 규칙이 우선, 2026-08-07). **면접관 질문도 문장으로 함께 쌓는다**(2026-08-07) — 턴은 «질문 → 답변» 이라 질문이 그 턴 첫 문장이고, 질문 시각에 턴이 넘어간다. 질문은 내 답변과 같은 모양으로 그리고(2026-08-10 — 앞에 세우던 Q 배지 폐기), 하이라이트 구간은 없다 — 면접관 발화의 문자 오프셋은 질문 문자열 기준이라 답변 대본에 대고 자르면 엉뚱한 대목이 나온다. 발화가 아예 없는 공백에는 직전 위치가 그대로 남는다 — 비었다 차는 깜빡임을 막는다. 위치 판정은 `VideoTranscript.position(at:)`(턴 + 문장 순번)이고 State 에 저장해 문장이 바뀔 때만 오버레이가 다시 그려진다.

대본 오버레이의 하이라이트는 리포트 카드와 같은 `TranscriptText` 규약(`AttributedString.link` + `openURL`)으로 부분 탭을 받는다 — 구간은 카드 좌표계에서 문장-로컬 오프셋으로 잘라 옮기고, 원본 구간 인덱스는 `Sentence.spanIndices` 로 돌려준다. 탭하면 영상을 멈추고 상세 시트를 올린다 — 그 시트엔 `[영상 보러가기]` 가 없고(이미 영상 안), 시트를 내리면 멈춰 둔 재생이 이어진다.

**상단에도 스크림을 늘 깐다** — 밝은 영상 위에서 X 가 읽히게 `VideoOverlay(.darkClose)` 를 위아래로 뒤집어 얹는다(2026-08-07, 시안 443:7902 상단 그라데이션 — DS 램프는 아래로 진해지는 방향뿐이라 방향만 화면이 뒤집는다).

**좌상단 X 는 이탈이 아니라 «뒤로»** 다. 리포트 이탈은 메인의 X 만 담당해서 플레이어는 `closeRequested` 를 갖지 않는다.

**진입 경로가 하단 버튼 하나를 가른다**(`State.Entry`): 메인 상세 시트의 «영상 보러가기» 로 들어오면 하단에 `[이전 화면으로 가기]`(시안 443:7828)가 서고, 메인 CTA «영상 다시보기» 로 들어오면 없다(443:7804). 화면은 한 벌이다 — 시트에서 왔다는 사실을 아는 건 메인이라 `videoRequested(startAt:entry:)` 에 실어 코디네이터가 State 에 박아준다(플레이어 안에서 시트를 열어 «영상 보러가기» 를 누르는 건 화면 이동이 아니라 seek 이라 `Entry` 와 무관하다).

**두 버튼이 가는 곳이 다르다**(사용자 결정 2026-08-06): 상단 X 는 `backRequested` 로 리포트 메인까지(시트는 닫힌 채), 하단 `[이전 화면으로 가기]` 는 `returnToHighlightSheetRequested` 로 **왔던 상세 시트까지** 되돌린다 — «이전 화면» 이 시트인데 메인까지 튀면 눌렀던 하이라이트를 다시 찾아야 한다. 시트와 push 를 동시에 띄울 수 없어서 메인이 시트 State 를 버리지 않고 `stashedHighlightDetail` 에 접어 두고, 코디네이터가 pop 하며 되살린다(X 로 나오면 비운다).

## 지인 피드백

`ReportPeerFeedbackFeature` — 메인의 `[지인에게 면접 영상 보내기]` 로 진입. 태도 항목 5종(시선·표정·자세·손동작·목소리)을 토글로 골라 공유 링크를 만드는 화면이다. 토글은 전부 켠 채 시작한다(HLT-70). 항목 이름·아이콘은 리포트 메인과 같은 `GuestAttitudeCopy` 표를 쓴다.

**평가 독립성**: 지인에게 넘기는 payload 는 영상과 질문 경계까지다. AI 피드백(하이라이트·진단·다음 대비)은 넘기지 않는다 — 지인 평가가 AI 평가에 오염되면 4.6 의 2축 비교가 무의미해진다. 그래서 이 화면이 서버로 보내는 것도 항목 코드뿐이다. 링크 생성 계약은 `DomainFeedbackShare`([[api#Feedback Share]]), 게스트 제출측은 [[feedback]].

**생성은 되돌릴 수 없다**: 항목은 생성 시점에 링크로 잠기고 면접당 활성 링크는 1개(409)다. 그래서 성공 직후 화면은 완료 팝업의 «링크 복사하기» 하나로 좁아진다. 잠긴 토글을 탭하면 값은 두고 «링크 생성 후 조작이 불가능합니다.» 토스트만 띄운다(HLT-70 — `.disabled` 가 탭을 삼켜 위에 투명 탭 판을 얹는다). 복사 후 메인 갱신은 당겨서 새로고침이 받는다(→ 1차 리포트). 토큰 → 지인 URL 조립은 클라이언트 몫 — 도메인은 `hilit.my` 확정(2026-07-29), 경로 구조는 웹 게스트 페이지 스펙 대기라 `shareLink(token:)` 한 곳에 모아 뒀다.

**복사가 이 화면의 끝이다** (2026-08-07 확정): 복사하면 생성 완료 판(`Modal` 443:8121)이 복사 완료 판(`HomeModal` 1321:10451 — 버튼 없음)으로 **바꿔 끼워지고**, 그 판이 2초 뒤 스스로 닫히며 리포트 메인으로 나간다. 두 판은 동시에 뜨지 않아 Bool 둘이 아니라 `Popup` enum 하나 + `hilitModal(item:)` 이다(선례 `InterviewSessionView` — 거기는 뷰에서 접지만 여기는 State 가 enum 을 갖는다). **시스템 공유 시트는 떼어냈다** — 자동 이탈과 시트가 같은 자리를 다툰다(그래서 «모달 닫힘 대기 400ms» 도 함께 사라졌고, `ShareSheet` 래퍼는 삭제). 복사 완료를 토스트로 두지 않은 이유도 같다 — 판 하나가 완료 통보와 이탈 타이머를 동시에 갖는다.

**상단 X 는 팝업 것이다** (2026-08-07 확정): 팝업이 떠 있으면 X 는 그 판만 닫고 화면은 남는다(링크는 손에 있고 항목은 잠긴 채라 CTA 로 다시 복사할 수 있다). 팝업이 없을 때만 X 가 화면을 나간다. 복사 완료 판의 X 는 예정된 자동 이탈을 끊고 즉시 나간다 — 어차피 도착지가 같아서 기다림만 건너뛴다.

**도착지는 진입에 따라 갈린다** (2026-08-10): 메인에서 push 된 흐름은 메인으로 pop 하지만, 마이페이지 [지인 피드백 받기] 로 **곧장 들어온** 흐름(`Entry.peerFeedback`)은 흐름째 닫혀 마이페이지 목록으로 돌아간다 — 보러 온 화면을 닫았는데 아래에서 안 보던 리포트가 드러나면 «뒤로» 가 아니다. 자동 이탈도 같은 신호(`backRequested`)를 쓰므로 이 규약을 함께 탄다 → [[report#코디네이터]].

**재생성은 없지만 재복사는 있다** (⚠️ prd-외 재량 — 링크 유실 막다른 길을 관례로 메웠다, 스펙 확정 시 재검토): 복사하지 못한 채 나가면 링크가 손에 남지 않는데 CTA 재탭은 409 로 막힌다. 그래서 진입 때 `FeedbackShareClient.status` 로 활성 링크를 회수한다 — 응답에 토큰이 있어 링크를 다시 조립할 수 있다(이 화면이 그 GET 의 첫 사용처). 회수하면 항목 토글을 잠그고 CTA 를 «링크 복사하기» 로 바꾸며, 생성이 409 로 걸려도 같은 회수로 완료 팝업을 다시 띄운다(제목만 «이미 만들어 둔 링크» 판으로 가른다 — 회수한 링크에 «생성 완료» 는 거짓이다). 진입 회수는 떠 있는 판을 건드리지 않는다. 항목은 화면에서 고른 값이 아니라 **응답의 `axes`** 로 덮는다(잠긴 값이 서버에 있다). ACTIVE 가 아닌 링크(무효화·비공개)는 복사해도 지인이 못 열어 회수하지 않고, 회수 자체가 실패하면 안내 토스트로 돌아간다(토스트 자리는 이제 생성·회수 실패 전용이다).

- 생성 실패 안내는 토스트가 기본이지만 **미승격 에러코드는 Alert 로 갈린다** — 클라가 번역할 문구가 없어 서버 원문을 공통 Alert(`serverAlertState()` — [[api#공통 규약]])로 띄운다. 토스트는 같이 띄우지 않는다(한 사건을 두 자리에 쓰지 않는다).
- 항목을 서버로 보내는 순서는 `AttitudeAxisKind.allCases` 로 고정한다 — `Set` 순회 순서는 실행마다 달라서 게스트 화면의 항목 순서가 흔들린다.
- 항목 0개는 CTA `.disabled` 로 막는다(서버도 0개면 400). 다크 화면용 disabled 변형이 시안에 없어 라이트용 g50 바로 그려진다 — 시안 나오면 교체.
- 클립보드는 Feature 안의 `PasteboardClient` seam — 네트워크 Repository 가 아니라 기기 IO 라 Domain 모듈 근거가 없다. 두 번째 사용처가 생기면 `CoreCommon` 승격 (기기 IO 인프라 — `FirstLaunchStore` 선례).

## 최종 보고서 화면은 없다

지인 피드백이 도착해도 화면이 늘지 않는다 — 결과는 **메인의 «지인 피드백» 섹션이 자라서** 보여준다(이름 탭 + 태도 평가 목록, 시안 443:7102). 그래서 별도 «최종 보고서» 화면·`Path` 케이스를 두지 않는다(2026-08-06, `ReportFinalFeature`/`View` 자리표시 골격 삭제 — 진입 조건도 화면 내용도 시안이 없었고, 도착 후 상태가 메인 안에서 끝나는 게 확정됐다).

«지인에게 면접 영상 보내기» 카드는 피드백이 도착한 뒤에도 남는다(«1/4») — 정원이 차기 전까지 다음 지인에게 또 보낼 수 있어야 해서다. 지인 vs AI 2축 비교가 별 화면으로 필요해지면 그때 다시 만든다.
